# CLAUDE.md

Guidance for Claude Code working in this repository.

## Conventions

- **A comment exists only where the code cannot document itself.** Docstrings: two lines at most,
  none that restate the symbol name, no `- Parameters:`/`- Returns:` sections — signatures are
  typed. Port narration, history, refactoring notes, architecture prose, restatement of the line
  beneath and banner comments all go. Two exceptions: `swift/Sources/KSPKit/Constants.swift`, where
  a bare `48` or `127` cannot self-document, so every value keeps a **one-line** comment with a spec
  pointer where one fits; and a genuine trap, one line, where behaviour reads as a bug a reader
  would otherwise "fix". Functional directives (`// swift-format-ignore` and the like) are never
  touched.
- Serena's tools for symbol work — but after `EnterWorktree` Serena still writes to the main
  checkout, so use `Edit` inside a worktree.
- Send wide greps, corpus dumps and spec lookups to the subagents in `.claude/agents/`.
- On pull requests: read the comments and act on them, leave the replies to the User.
- A Claude plan file committed here is deleted by the task that implements it.

[The app's visual language](docs/design/visual-language.md) — **read it before touching
`KSPApp` styling.** Colours and metrics come from `DesignTokens.swift`, never a literal in a
view; hue never carries text contrast, status never relies on hue, and `C3` is MIDI 60.

## What this is

Converts Standard MIDI files ↔ Arturia KeyStep Pro `.KeyStepPro` project files. MIDI Control
Center has no MIDI export for it, so this tool's is the only one that exists, and there is no render
to check against: **the hardware's live MIDI output is the sole ground truth.** The automated
hardware tests live in the Python archive until #314 ports them — **green CI ≠ verified on
hardware.**

- [Format spec](analysis/KeyStepPro_Format_Spec.md) — **read it before touching format code.**
- [ROADMAP.md](ROADMAP.md) — milestones, status, release track. Issues are GitHub issues on
  `bauerc/KeystepProTool`, driven through `gh`; triage labels and skill conventions in
  [docs/agents/](docs/agents/).
- [CONTEXT.md](CONTEXT.md), [docs/adr/](docs/adr/) — domain model and decisions. **The device's

- The Swift is the only implementation. The Python is archived at `python-final`

## Commands

Swift 6.2, Command Line Tools, no Xcode.

```sh
./scripts/validate.sh            # swift-format lint and swift test; also the Stop hook
make app                         # build the app under swift/.build/app/ (make install: to /Applications)
./scripts/gen_bulk_fixtures.sh   # after tools/gen_bulk_plan.swift or a pool-gate change; review the diff
./scripts/bench_read.sh          # read cost, for analysis/Read_Cost.md
```

**Swift tests go through `./scripts/validate.sh`, never `swift test` directly** — it adds the three
flags a Command Line Tools install needs (swift/README.md §6). `BulkPlan.swift` is generated by
`tools/gen_bulk_plan.swift` from MCC's descriptor after a firmware update; never edit it by hand.

## Architecture

`swift/` is one SwiftPM package, and two invariants bind an edit: **nothing may add a dependency
to `KSPKit`**, and **a command body goes in `KSPRun`**, never in `KSPSwiftCLI` or `KSPApp`,
because both faces must run the very same `convert`. `KSPKit` prints nothing, reads no arguments
and decides no file paths. See swift/README.md §5.

**The CLI's output is a byte-for-byte contract, held by its tests.** A diagnostic's wording, a
key's position in the JSON and a number's formatting are all load-bearing: change one, and change
the test that pins it in the same commit. Exit codes are load-bearing too: **0 success, 1 file or
format failure, 2 usage failure** (`ExitCodeTests`).

`KSPMIDI`'s export has three layers that must stay separate: `renderPattern` (pattern → tick
data), `arrange` (timeline placement) and `buildMIDIFile` (the file). Import mirrors it inverted:
`readClip` → `quantise` → `apply`. Tests assert on `Rendering` and `Placement` data, never on
parsed MIDI.

## Repository data is not source

`project_files/*.KeyStepPro`, `analysis/*.txt`, `fixtures/*_tape.txt` and
`swift/Sources/KSPRun/Resources/Default.KeyStepPro` are data — never reformat, re-indent, or add a
final newline. The exports are M3's byte-identical baseline, the bundled template must stay
byte-identical to `project_files/Default.KeyStepPro`, and the `.txt` files are transcribed from the
hardware display and cannot be regenerated without the device. `FormatInvariantsTests` fails
loudly on such corruption; the fix is never in that file.
